This portfolio keeps MDX enabled because it is useful when a note needs a component, a live example, or a more structured way to explain a technical idea. The key is to use it intentionally, not because the tool exists.

## Why MDX?

MDX works best when it helps the reader understand something faster. A small embedded component can clarify a workflow, show a state transition, or demonstrate a pattern that plain Markdown would struggle to express cleanly.

If the content does not benefit from interactivity or composition, plain Markdown is usually the simpler, better-maintained choice.

## Example

Here is how you import and use a UI component inside of MDX. When a component improves clarity, the extra structure is worth it.

import HeaderLink from '../../components/HeaderLink.astro';

<HeaderLink href="#" onclick="alert('clicked!')">
	Embedded component in MDX
</HeaderLink>
